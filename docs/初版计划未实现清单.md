## ② 语气感知与迁移（计划要求做成"专门 Skill"）

- **②-1 缺客服安抚风、幽默调侃风等预设，且无独立"语气 Profile"层**：计划 ② 要求预设语气 Profile（技术文档严肃风、客服安抚风、学术客观风、幽默调侃风）；`scene/service.py` 的 `BUILTIN_PROFILES` 只有学术技术·中性 / 商务·正式 / 产品文案·营销 / 日常·随性 4 个场景档案，语气与场景强耦合，客服安抚、幽默调侃两类无对应档案。
- **②-2 输入侧语气自动识别未实现**：计划 ② 要求自动识别原文语气（如 `[angry]`、`[sarcastic]`）；`emotion/parser.py` 的 `_VALID_EMOTIONS` 只接受模型输出的 positive/negative/urgent/apology/emphasis/humor 六类，没有输入侧方括号语气标签解析、无反讽/讽刺检测，识别结果也不注入翻译 prompt。
- **②-3 "专门 Skill"形态未实现**：计划 ② 标题即"专门 Skill"；代码中无 skill 包/注册/工具调用机制（全项目检索 `skill`、`tool_call` 无 Python 命中），语气控制仅是 `PromptComposer.compose()` 里拼字符串。
- **②-4 输出侧"语气保留"未闭环**：计划 ② 要求输出侧用 prompt 控制语气保留；`PromptComposer` 仅注入场景的 descriptors/do/dont 风格描述，没有"须保留原文语气 X"的指令，`qa/service.py` 的 6 项质检（长度/数字/术语/残留/结构/一致性）也不含语气一致性校验。
- **②-5 用户自定义语气规则未实现**：计划 ② 举例"所有疑问句翻译成中文时保持礼貌委婉"；`SceneProfile.rules` 字段始终为空且 `PromptComposer` 从不读取，无规则编辑入口、无按句式类型执行的规则引擎（仅有自由文本 do/dont）。

## ③ 情感概率可视化（辅助判断手段）

- **③-1 积极/消极/中性概率百分比未实现**：计划 ③ 要求输出情感类别的概率百分比；`shared/dto.py: EmotionAnnotation` 只有 `{emotion 标签, intensity 1~3, confidence 恒 1.0, ...}`，无概率分布字段，`emotion/parser.py` 也不向模型索取概率，"情感分析概率模型"尚未接入。
- **③-2 仪表盘 / 小气泡展示未实现**：计划 ③ 要求"😊 87% 积极 | 😠 3% 消极"式展示；`SegmentList.tsx: EmotionBadges` 只渲染中文文字徽章（正面/负面/紧急…）+ 强度 `+n`，无百分比、无仪表盘、无气泡。
- **③-3 低置信阈值提醒 部分实现：缺百分比数值与"建议人工复核"提示**：计划 ③ 要求置信度低于阈值（如 60%）自动高亮并建议人工复核；阈值与高亮已做（`qa/service.py: ConfidenceEstimator` 0.60 分档、`pipeline.py: _annotate` 产出 `low_confidence` span、`SegmentList.tsx: segment--low` 黄底），但界面只显示"低置信"档位，不显示具体分值，也没有"建议人工复核"文案（`ConfidenceResult.threshold` 字段未参与提示）。

## ④ 个人术语库 + 机器自动更新

- **④-1 后台定时爬取未实现**：计划 ④ 要求后台定时爬取 arXiv、顶级会议、行业新闻、专利库；代码无任何网络抓取、来源清单或定时调度（无 scheduler/APScheduler/thread 定时器），`services.py: glossary_discover` 只对调用方传入的 `text`/`docs` 做规则抽取。
- **④-2 候选译词生成未实现**：计划 ④ 要求"提取新术语并生成候选翻译"；`glossary/discovery.py: CandidateExtractor` 只产出 `source_term`（`target_text=None`、`target_source="none"`），译词必须由用户手填，无模型生成候选译法。
- **④-3 候选推送与候选列表界面未实现**：计划 ④ 要求把候选翻译"推送"给用户；`glossary.discover` 仅能手动调用并返回当次 50 条，无后台任务/通知通道；前端检索 `discover`/`候选` 无任何入口（`docs/frontend-contract.md` §5.3 规划的"工作台侧栏 术语候选"未实现）。
- **④-4 社区共享池与官方术语包在线源未实现**：计划 ④ 要求用户匿名贡献术语、经审核纳入全局池，3.2 还要求开源术语库下载到本地；`community.list/add/sync/remove` 全是桩（`services.py: community_list` 返回 `{"items": []}`、`community_add` 直接回显 `accepted=True`、`community_sync` 返回 `synced: 0`），`ports.py: ReleaseFeedPort` 只有协议定义无任何实现，`glossary.package.list` 只是列出本地词库，无官方包下载与审核流程。
- **④-5 会话级覆盖 部分实现：缺命令入口、匹配接线与 UI**：计划 ④ 要求"当前会话临时改术语译法，不影响个人库"；`glossary/service.py: session_override()` 已定义但全项目无调用方——`bridge/command.py` 无对应命令、`glossary.match()` 不读 `_overrides`、优先级阶梯只预留 session scope、前端无入口。

## ⑦ 翻译显示与透明化

- **⑦-1 区别样式缺后端数据源 部分实现：缺 alternate_translation / common_translation span 与候选译法**：计划 ⑦ 要求对不同译文给略有区别的样式，表明"存在其他译法"或"当前为常用译法"；前端 `SpanRenderer.tsx: KIND_CLASS` 已把 `alternate_translation/common_translation` 映射到 `span--alt/--common`（`global.css` 只有 `.span--alt` 虚线与 `.span--kept` 斜体，`.span--common` 无样式），但 `pipeline.py: _annotate()` 只产出 `terminology_applied` 与 `low_confidence` 两类 span，无候选译法生成，`variants` 仅在术语命中处填 1 条自身 label。
- **⑦-2 气泡提示未实现**：计划 ⑦ 要求在带区别样式的译文上弹出气泡查看/选择不同译文；`SpanRenderer.tsx` 只用 HTML `title` 属性做原生 tooltip，无气泡组件、无"选择其他译文"交互，`bridge/command.py` 也无对应命令（`docs/frontend-contract.md` §5.1 写的"结果区…/气泡"未兑现）。
- **⑦-3 混合语言下划线未实现**：计划 ⑦ 要求"译为中文时，原本就是中文的内容下方加浅色细下划线；译为其他语言时无此特殊样式"；后端无 `source_lang_kept` span 生成（`shared/types.py` 只有 Kind 枚举、`global.css: .span--kept` 仅是斜体样式，且全项目从未赋值），`text/service.py: LanguageDetector` 只给整体 `mixed` 粗提示，不逐段/逐字符识别源文中的中文片段。
- **⑦-4 透明化统一显示层 部分实现：缺情感概率、候选译法与统一气泡**：计划 ⑦ 要求样式/气泡与置信度评分、情感概率、直译标识统一在显示层呈现；`SegmentList.tsx` 已同段展示置信度档位、情感徽章、风险、直译标识与术语点线，但缺情感概率（见 ③-1/③-2）、缺候选译法气泡（见 ⑦-2），透明化信息未形成统一面板。

## 3.2 技术栈中未采用 / 未落地的部分

- **3.2-1 LangChain / LangGraph 未采用**：计划要求用 LangChain/LangGraph 做 Agent 编排（工作流定义、工具调用、路由分发）；实际零三方依赖（`pyproject.toml: dependencies = []`），编排是自研 `app/pipeline.py`（S0–S6）+ `app/facades.py`，无 Agent 框架、无工具调用/路由分发抽象。
- **3.2-2 LlamaIndex + ChromaDB 向量检索未实现**：计划要求本地运行向量库，对术语库/翻译记忆/风格指南做实时检索；代码无 embedding/向量库依赖与模块，翻译记忆是 SQLite 上的 exact/fuzzy/keyword 匹配（`tm/service.py`），术语是正则+最长匹配（`glossary/matcher.py`）。
- **3.2-3 情感分析概率模型未落地**：计划 3.2 明确"情感分析（概率输出模型选型待定）"；当前无独立情感模型，`emotion/parser.py` 只解析主翻译模型 JSON 里的 `emotions` 字段，概率输出能力缺失。
- **3.2-4 DeepL API（批量）未接入**：计划主模型含 DeepL API（批量）；`infra/providers/openai_compat.py: PROVIDER_PRESETS` 只有 deepseek / openai / claude 三个 OpenAI 兼容预设，无 DeepL 协议适配、无批量翻译接口。
- **3.2-5 Whisper large-v3（ASR）未接入**：计划进阶语音用 Whisper large-v3；项目无音频依赖、无转写模块、无流式音频处理。
- **3.2-6 Azure Neural TTS 未接入**：计划进阶语音用 Azure Neural TTS；仅在 `shared/events.py` 预留了 `"tts.chunk"` 事件名，无任何合成实现。
- **3.2-7 文档解析（Unstructured.io / PyMuPDF）未接入**：计划用其在后续文档/PDF 翻译中保留格式；项目无该依赖、无解析模块，输入仅纯文本。
- **3.2-8 开源术语库在线下载/更新未实现**：计划要求把开源文件（如开源术语库）下载到本地后使用；`ports.py: ReleaseFeedPort`（list_manifests / fetch_package）只有协议定义、无实现与源注册，术语包只有本地 JSON 导入导出（`glossary.import/export`）。
- **3.2-9 本地文件形式的偏好/术语存储未落地**：计划本地存储为"SQLite + 本地文件（JSON 术语库、偏好文件）"；`infra/persistence/jsonstore.py: JsonFileStore` 定义后全项目无引用，术语与场景偏好全部落 SQLite（`.laa/laa.sqlite3`），无偏好 JSON 文件。
